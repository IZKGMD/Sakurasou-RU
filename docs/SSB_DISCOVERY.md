# Первый анализатор сценария SSB (PS Vita PCSG00129)

## Подтверждено на реальном файле

Проверен пользовательский файл `SCN_CJIN_1Y_1112x_010.ssb` (190 804 байта, SHA-256 `bfddd7fb3f322a289a9f9df70b0699184e4b6c4ed7d72a4fca1da7d27d247add`).

В районе `0x2C160` обнаружена строка `START : SCN_...`; далее идут **87 последовательных наборов** следующего типа:
- имя файла озвучки (`.hca`);
- имя говорящего (UTF-8);
- повтор имени озвучки;
- диалоговая реплика (UTF-8, с игровым маркером `▼`).

В примере 174 записи имени аудиофайла, 87 кандидатов на имена говорящего и 87 реплик. Все 87 наборов соответствуют этому порядку и совпадению обеих ссылок на озвучку. Тексты NUL-терминированы, начинаются по смещениям, кратным 4, и выровнены нулевыми байтами. **Это доказано для одного образца, а не для всех сценариев игры.**

Файл содержит и другие UTF-8 строки: технические сообщения, имена объектов, игровые ресурсы. Поэтому поиск всех печатных текстов без границ сценария приводит к шуму.

## Запуск на Windows

Обновите `tools/ssb_extract.py` из этого репозитория. Убедитесь, что локальный SSB находится по пути `work/samples/SCN_CJIN_1Y_1112x_010.ssb`.

```powershell
py -3 .\tools\ssb_extract.py ".\work\samples\SCN_CJIN_1Y_1112x_010.ssb" --csv ".\work\translations\CJIN_010.csv" --report ".\work\reports\CJIN_010.json"
```

Локальный CSV будет включать поля:
- `id` и `offset_hex` — стабильная привязка к байтовому смещению в **исходном** файле;
- `original_bytes` — размер японского UTF-8 в байтах;
- `speaker_candidate` и `voice_candidate` — предполагаемый говорящий и файл озвучки;
- `source_ja` — оригинальная японская реплика;
- `translation_ru` — пустое поле для русского текста;
- `notes` — комментарии редактора.

CSV сохраняется в локальной папке `work/`, которая исключена из Git. JSON отчёт содержит только технические количества и SHA-256, без диалогов.

## Ограничения

**Этот скрипт только извлекает строки. Он НЕ умеет безопасно заменять их в SSB.** Сценарные команды, ссылки на константы, таблица смещений, длины строк и возможные ограничения шрифта ещё не исследованы. Вставлять UTF-8 прямо в байты, менять длину строк или удалять символ `▼` нельзя: это может нарушить работу игры. Переводческую таблицу пока ведите только как черновик.

Кодировка UTF-8 подтверждена на **отдельных строках этого файла**. Нет гарантий, что все прочие файлы SSB и другие текстовые ресурсы используют идентичный формат.

Исходные сценарии и заполненные оригинальными репликами CSV **не публикуйте** в открытом репозитории. Для дальнейшего анализа достаточно JSON-отчёта или приватного предоставления отдельного образца.
